i

Про Material UI: зачем и как

Material UI (MUI) — библиотека готовых React-компонентов в стиле Material Design от Google. Документация: mui.com/material-ui/all-components

Зачем мы его используем

  • Не верстаем с нуляКнопки, поля ввода, карточки, модальные окна, таблицы и меню уже готовы и хорошо выглядят.
  • Единый стильКомпоненты сочетаются друг с другом: одинаковые отступы, шрифты, скругления.
  • ТемыЦвета задаются в одном месте (theme.ts), и тёмная тема сразу работает для всех компонентов.
  • ДоступностьРабота с клавиатуры, фокус и aria-атрибуты уже настроены.
  • ПопулярностьБольшое сообщество, подробная документация с примерами, часто встречается в реальных проектах.

Как использовать

1Импортируем компонент из @mui/material и используем как обычный React-компонент

2Настраиваем через props

У большинства компонентов есть variant, color, size, disabled:

Варианты кнопок

<Stack direction="row" spacing={2}>
  <Button variant="text">Text</Button>
  <Button variant="outlined">Outlined</Button>
  <Button variant="contained">Contained</Button>
  <Button variant="contained" color="error" size="small">Удалить</Button>
</Stack>

4Собираем вместе

Пример маленькой формы: поле ввода, кнопка с иконкой и текст, который меняется при вводе.

src/components/MuiDemo.tsx
import { useState } from 'react';
import { Box, Button, Stack, TextField, Typography } from '@mui/material';
import SendIcon from '@mui/icons-material/Send';

export const MuiDemo = () => {
  const [name, setName] = useState('');

  return (
    <Box sx={{ p: 3, bgcolor: 'background.paper', borderRadius: 2 }}>
      <Typography variant="h5" gutterBottom>
        Привет, {name || 'гость'}!
      </Typography>

      <Stack direction="row" spacing={2}>
        <TextField
          label="Ваше имя"
          size="small"
          value={name}
          onChange={(e) => setName(e.target.value)}
        />
        <Button
          variant="contained"
          endIcon={<SendIcon />}
          disabled={!name}
          onClick={() => alert(`Отправлено: ${name}`)}
        >
          Отправить
        </Button>
      </Stack>
    </Box>
  );
};

Создаём тему: светлая и тёмная

src/theme/theme.ts
import { createTheme } from '@mui/material/styles';

export const theme = createTheme({
  // MUI создаст CSS-переменные (--mui-palette-...), их можно использовать в SCSS
  cssVariables: { colorSchemeSelector: 'data' },
  colorSchemes: {
    light: {
      palette: {
        primary: { main: '#1976d2' },
        background: { default: '#f5f5f5', paper: '#ffffff' },
      },
    },
    dark: {
      palette: {
        primary: { main: '#90caf9' },
        background: { default: '#121212', paper: '#1e1e1e' },
      },
    },
  },
  // Контрольные точки экрана. Оставляем стандартные значения MUI:
  // xs: 0, sm: 600, md: 900, lg: 1200, xl: 1536.
  // Если понадобится другая ширина (например, xl: 1440), задаём её здесь:
  // breakpoints: {
  //   values: { xs: 0, sm: 600, md: 900, lg: 1200, xl: 1440 },
  // },
  components: {
    // Любой <Container> по умолчанию будет шириной до xl (1536px)
    MuiContainer: {
      defaultProps: { maxWidth: 'xl' },
    },
  },
});
  • colorSchemes — цвета для светлой и тёмной темы.
  • components.MuiContainer — настройки по умолчанию для компонента Container. Теперь любой <Container> в проекте ограничен шириной xl (1536px) и стоит по центру.
  • breakpoints — ширины экрана, на которых меняется раскладка. Мы оставляем стандартные значения MUI.
Если нужна другая ширина

Например, по дизайну контент шириной 1440px: раскомментируйте блок breakpoints в theme.ts и поменяйте xl. Ширина изменится для всего сайта.

Учтите: xl — это ещё и контрольная точка для адаптивности. Если её поменять, Grid и theme.breakpoints.up('xl') тоже начнут срабатывать на новой ширине.

Подключаем тему

src/main.tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { ThemeProvider } from '@mui/material/styles';
import CssBaseline from '@mui/material/CssBaseline';
import { theme } from './theme/theme';
import App from './App';

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <ThemeProvider theme={theme} defaultMode="system">
      <CssBaseline />
      <App />
    </ThemeProvider>
  </StrictMode>,
);
  • ThemeProvider раздаёт тему всем компонентам.
  • CssBaseline сбрасывает стили браузера и красит фон под текущую тему.
  • defaultMode="system" — по умолчанию берётся тема из настроек ОС.
Это удобно

Выбор пользователя MUI сам сохраняет в localStorage. После перезагрузки страницы тема останется.

6

Кнопка переключения темы

src/components/Header/ThemeToggle.tsx
import { IconButton, Tooltip } from '@mui/material';
import { useColorScheme } from '@mui/material/styles';
import DarkModeIcon from '@mui/icons-material/DarkMode';
import LightModeIcon from '@mui/icons-material/LightMode';

export const ThemeToggle = () => {
  const { mode, systemMode, setMode } = useColorScheme();

  if (!mode) return null; // тема ещё не определилась

  const current = mode === 'system' ? systemMode : mode;
  const isDark = current === 'dark';

  return (
    <Tooltip title={isDark ? 'Светлая тема' : 'Тёмная тема'}>
      <IconButton color="inherit" onClick={() => setMode(isDark ? 'light' : 'dark')}>
        {isDark ? <LightModeIcon /> : <DarkModeIcon />}
      </IconButton>
    </Tooltip>
  );
};

Шапка и Layout на компонентах MUI

Используем готовые компоненты MUI:

  • AppBar — шапка, фон на всю ширину экрана;
  • Toolbar — строка внутри шапки;
  • Container — ограничивает ширину (у нас до xl, 1536px) и ставит контент по центру;
  • Box с component="main" — тег <main> с отступами через sx.
src/components/Header/Header.tsx
import { AppBar, Container, Toolbar, Typography } from '@mui/material';
import { ThemeToggle } from './ThemeToggle';

export const Header = () => {
  return (
    // фон шапки — на всю ширину экрана
    <AppBar
      position="static"
      color="inherit"
      elevation={0}
      sx={{ borderBottom: 1, borderColor: 'divider' }}
    >
      {/* а содержимое — внутри контейнера */}
      <Container>
        <Toolbar disableGutters sx={{ justifyContent: 'space-between' }}>
          <Typography variant="h6" component="h1" color="primary">
            Мой первый проект
          </Typography>
          <ThemeToggle />
        </Toolbar>
      </Container>
    </AppBar>
  );
};

disableGutters убирает у Toolbar собственные отступы. Их уже даёт Container, поэтому шапка выровнена по краям с контентом.

Layout — общий каркас для всех страниц: шапка сверху, под ней контент в контейнере. Новую страницу достаточно обернуть в <Layout>.

src/components/Layout/Layout.tsx
import type { ReactNode } from 'react';
import { Box, Container } from '@mui/material';
import { Header } from '../Header/Header';

type LayoutProps = {
  children: ReactNode;
};

export const Layout = ({ children }: LayoutProps) => {
  return (
    <>
      <Header />
      <Box component="main" sx={{ py: 4 }}>
        <Container>{children}</Container>
      </Box>
    </>
  );
};

children — это всё, что положили между тегами: <Layout>вот это</Layout>.

8

SCSS Modules

Правило

Файл называется Имя.module.scss. Классы из него работают только в том компоненте, куда импортированы, поэтому конфликтов имён не будет.

MUI отвечает за готовые компоненты, а SCSS-модули — за нашу собственную вёрстку.

Общие переменные для всего проекта

Отступы, скругления и другие общие значения храним в одном файле. Поменяли там — поменялось во всём проекте.

src/styles/_variables.scss
// Общие переменные проекта — меняем здесь, и они меняются везде.
// Подключаем в нужный файл: @use '<путь до src>/styles/variables' as *;

// Отступы
$gap-small: 8px;
$gap: 16px;
$gap-large: 32px;

// Скругления
$radius: 8px;

Подключаем этот файл в начале любого .scss, где нужны переменные, строкой @use. Путь относительный, как у обычного импорта:

Где лежит ваш .scssЧто пишем в первой строке
src/App.module.scss@use './styles/variables' as *;
src/components/Header/Header.module.scss@use '../../styles/variables' as *;

as * значит «использовать переменные напрямую»: пишем $gap, а не variables.$gap. Подчёркивание и .scss в пути не пишем.

Используем в компоненте

src/App.module.scss
// Подключаем общие переменные проекта
@use './styles/variables' as *;

.content {
  display: flex;
  flex-direction: column;
  align-items: flex-start; // кнопка не растягивается на всю ширину
  gap: $gap;
}

.hint {
  margin: 0;
  padding-left: $gap-small;
  // цвета берём из темы MUI — они сами меняются при переключении
  color: var(--mui-palette-text-secondary);
  border-left: 3px solid var(--mui-palette-primary-main);
}

Собираем страницу

src/App.tsx
import { useState } from 'react';
import { Button, Card, CardContent, Typography } from '@mui/material';
import { Layout } from './components/Layout/Layout';
import styles from './App.module.scss';

function App() {
  const [count, setCount] = useState(0);

  return (
    <Layout>
      <div className={styles.content}>
        <p className={styles.hint}>
          Переключите тему в шапке — цвета этого текста тоже поменяются.
        </p>
        <Card>
          <CardContent>
            <Typography variant="h5">Счётчик: {count}</Typography>
          </CardContent>
        </Card>
        <Button variant="contained" onClick={() => setCount(count + 1)}>
          Нажми меня
        </Button>
      </div>
    </Layout>
  );
}

export default App;

Глава 2

Компоненты и хуки

Какие бывают компоненты, какие хуки есть и зачем они нужны, когда выносить код в отдельный компонент и в какую папку его класть.

2.1

Что такое компонент

Компонент — это функция, которая возвращает разметку (JSX). Из компонентов, как из кубиков, собирается всё приложение: App → Layout → Header → ThemeToggle.

Hello.tsx
export const Hello = () => {
  return <h2>Привет!</h2>;
};

// используем как тег
<Hello />
  • Имя всегда с большой буквы: Hello, а не hello.
  • Возвращает один корневой элемент. Если нужно несколько, оборачиваем в <>...</> (фрагмент).
  • Один компонент — один файл с тем же именем: Hello.tsx.
Классовые компоненты

Раньше писали class Hello extends React.Component. Сейчас пишем только функциональные компоненты. Классовые встретятся разве что в старых проектах.

2.2

Props — входные данные компонента

Props — это «атрибуты» компонента. Через них родитель передаёт данные внутрь. Тип props описываем через type:

ProductCard.tsx
type ProductCardProps = {
  title: string;
  price: number;
};

export const ProductCard = ({ title, price }: ProductCardProps) => {
  return (
    <div>
      <h3>{title}</h3>
      <p>{price} ₽</p>
    </div>
  );
};

// использование
<ProductCard title="Наушники" price={4990} />
  • step?: number — знак ? делает проп необязательным. Значение по умолчанию задаём прямо в параметрах: ({ step = 1 }).
  • children — особый проп: всё, что положили между тегами. Мы уже использовали его в Layout.
  • Props только для чтения, внутри компонента их не меняем.
2.3

Какие бывают компоненты

  • UI-компоненты

    Только показывают то, что пришло в props. Без запросов и сложной логики, поэтому их легко переиспользовать.

    ProductCard Avatar PriceTagsrc/components/
  • Блоки (виджеты)

    Крупный кусок экрана со своей логикой и состоянием.

    Counter LoginForm ProductListsrc/components/
  • Layout

    Каркас: шапка, подвал, контейнер. Страницу кладём внутрь через children.

    Layout Headersrc/components/
  • Страницы

    Целый экран. Собирают блоки вместе и отвечают за конкретный адрес.

    HomePage ProfilePagesrc/pages/

Плюс готовые компоненты библиотек, у нас это MUI (Button, Card, TextField). Свои компоненты часто собираются из них.

2.4

Хуки

Хук — функция, которая начинается с use и даёт компоненту дополнительные возможности: память, реакцию на изменения, доступ к DOM.

Основные хуки

ХукДля чегоКогда нужен
useStateХранит данные, при изменении которых компонент перерисовываетсясчётчик, открыто/закрыто, текст в поле
useEffectВыполняет код после отрисовки: запросы, таймеры, подпискизагрузить данные, поменять document.title
useRefСсылка на DOM-элемент или значение, которое не вызывает перерисовкупоставить фокус в поле, хранить id таймера
useContextДостаёт общие данные без передачи props через все уровнитема, текущий пользователь, язык
useMemoЗапоминает результат тяжёлого вычисленияфильтрация и сортировка большого списка
useCallbackЗапоминает функцию между перерисовкамипередаём функцию в оптимизированный компонент
useReducerКак useState, но для сложного состояния с разными действиямикорзина, многошаговая форма
useIdУникальный idсвязать <label> и <input>
Для начала хватит трёх

useState, useEffect, useRef (выделены в таблице). useMemo и useCallback нужны для оптимизации, без них всё работает.

Хуки из MUI, которые пригодятся: useColorScheme (тема, уже используем), useTheme (достать значения темы), useMediaQuery (проверить ширину экрана).

useState — память компонента

useState
const [isOpen, setIsOpen] = useState(false);
//     ↑ значение  ↑ функция для изменения   ↑ начальное значение

<button onClick={() => setIsOpen(!isOpen)}>
  {isOpen ? 'Скрыть' : 'Показать'}
</button>

Меняем значение только через setIsOpen. Если новое значение зависит от старого, передаём функцию: setCount((prev) => prev + 1).

useEffect — действие после отрисовки

useEffect
// выполняется после отрисовки и каждый раз, когда меняется count
useEffect(() => {
  document.title = `Счётчик: ${count}`;
}, [count]);

Второй аргумент — массив зависимостей:

МассивКогда выполнится
[count]при появлении компонента и при каждом изменении count

Если запустили таймер или подписку, возвращаем функцию очистки:

useEffect с очисткой
useEffect(() => {
  const id = setInterval(() => setSeconds((s) => s + 1), 1000);

  // функция очистки — когда компонент исчезает
  return () => clearInterval(id);
}, []);

useRef — доступ к элементу

useRef

Правила хуков

  1. Вызываем только внутри компонента или своего хука.
  2. Только на верхнем уровне: не внутри if, циклов и обычных функций.
  3. Имя своего хука всегда начинается с use.

Свои хуки

Если логика повторяется или мешает читать разметку, выносим её в свой хук в папку src/hooks/:

src/hooks/useCounter.ts
import { useState } from 'react';

// Свой хук: логика счётчика отдельно от разметки
export const useCounter = (initialValue = 0, step = 1) => {
  const [count, setCount] = useState(initialValue);

  const increment = () => setCount((prev) => prev + step);
  const reset = () => setCount(initialValue);

  return { count, increment, reset };
};

Как понять, что пора создавать компонент

Выносите кусок разметки в отдельный компонент, если ответ «да» хотя бы на один вопрос:

  • Повторяется?Один и тот же блок встречается 2 раза и больше: карточки товаров, пункты меню.
  • Можно назвать?У куска есть понятное имя: «шапка», «форма входа», «карточка товара».
  • Своя логика?У куска есть своё состояние или обработчики: открыть/закрыть, ввод текста.
  • Файл разросся?Компонент длиннее 100–150 строк, и в нём трудно ориентироваться.

Не нужно создавать компонент ради одного <div> или одной строки текста. Слишком мелкое дробление тоже мешает читать код.

Частые ошибки с компонентами и хуками

  • Меняем состояние напрямуюcount++ или items.push(...): React не узнает об изменении и не перерисует компонент. Всегда через setCount(...), для массивов — новый массив: setItems([...items, newItem]).
  • useEffect без массива зависимостей и с setState внутриПолучится бесконечная перерисовка.
  • Хук внутри ifReact путает хуки между отрисовками. Хуки всегда пишем сверху компонента.
  • Читаем состояние сразу после setStateНовое значение появится только при следующей отрисовке.
  • Забыли key в спискеПри выводе массива через map каждому элементу нужен уникальный key: items.map((item) => <ProductCard key={item.id} ... />).
  • Меняем props внутри компонентаProps только для чтения. Если значение нужно менять, заводим useState или просим об этом родителя.

Глава 3

Жизненный цикл компонента

Как компонент появляется, обновляется и исчезает, когда React его перерисовывает и как управлять этими моментами через useEffect.

3.1

Три этапа жизни

У каждого компонента есть «жизнь»: он появляется на странице, обновляется и исчезает.

  1. 1 разМонтированиеmount

    Компонент впервые появился на странице: открыли страницу, показали модалку.

  2. сколько угодно разОбновлениеupdate

    Компонент перерисовался с новыми данными: нажали «+1», ввели текст в поле.

  3. 1 разРазмонтированиеunmount

    Компонент убрали со страницы: закрыли модалку, перешли на другую страницу.

3.2

Когда компонент перерисовывается

Компонент обновляется, то есть React заново вызывает функцию компонента, если:

  1. Изменилось его состояние: вызвали setState.
  2. Изменились его props: родитель передал новые данные.
  3. Перерисовался родитель: дети перерисовываются вместе с ним.
  4. Изменился контекст, который компонент читает через useContext.
Перерисовка — не перезагрузка

React вызывает функцию, сравнивает новый результат со старым и меняет в браузере только то, что изменилось.

Что происходит при каждой отрисовке

  1. RenderReact вызывает функцию компонента и получает JSX
  2. CommitReact обновляет DOM, то есть то, что видно на странице
  3. Effectsзапускаются useEffect, у которых изменились зависимости
3.3

Жизненный цикл через useEffect

В функциональных компонентах всеми этапами управляет useEffect:

ЭтапКак поймать
МонтированиеuseEffect(() => { ... }, [])
ОбновлениеuseEffect(() => { ... }, [value])
Размонтированиеreturn () => { ... } внутри useEffect

Посмотрите, в каком порядке появляются сообщения в консоли браузера (F12 → Console):

LifecycleDemo.tsx
import { useEffect, useState } from 'react';

export const LifecycleDemo = ({ name }: { name: string }) => {
  const [count, setCount] = useState(0);

  // 1. Рендер: тело функции выполняется при КАЖДОЙ отрисовке
  console.log('render', { name, count });

  // 2. Монтирование и размонтирование
  useEffect(() => {
    console.log('mount: компонент появился на странице');

    return () => {
      console.log('unmount: компонент убрали со страницы');
    };
  }, []);

  // 3. Обновление: срабатывает, когда изменился count
  useEffect(() => {
    console.log('update: count стал', count);
  }, [count]);

  return <button onClick={() => setCount(count + 1)}>{name}: {count}</button>;
};

Почему в консоли всё по два раза?

В режиме разработки <StrictMode> специально монтирует компонент, сразу размонтирует и монтирует снова. Так он находит эффекты без функции очистки. В собранном проекте (npm run build) такого нет. Это нормально, ничего не сломалось.

3.4

Практика: загрузка данных

Самая частая задача для useEffect — загрузить данные с сервера, когда компонент появился, и перезагрузить, когда изменился параметр:

UserCard.tsx
import { useEffect, useState } from 'react';

type User = {
  id: number;
  name: string;
};

export const UserCard = ({ userId }: { userId: number }) => {
  const [user, setUser] = useState<User | null>(null);
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    const controller = new AbortController();
    setIsLoading(true);

    fetch(`https://jsonplaceholder.typicode.com/users/${userId}`, {
      signal: controller.signal,
    })
      .then((res) => res.json())
      .then((data: User) => setUser(data))
      .catch(() => {}) // запрос отменён или ошибка сети
      .finally(() => setIsLoading(false));

    // userId поменялся или компонент исчез → отменяем старый запрос
    return () => controller.abort();
  }, [userId]);

  if (isLoading) return <p>Загрузка...</p>;
  if (!user) return <p>Пользователь не найден</p>;

  return <h3>{user.name}</h3>;
};
  • Монтирование запрос уходит первый раз.
  • Обновление поменялся userId: старый запрос отменяется, уходит новый.
  • Размонтирование ушли со страницы: запрос отменяется, setUser не вызовется у исчезнувшего компонента.

Почему useEffect(..., []) срабатывает 2 раза при разработке

Откройте вкладку Network (F12). При запуске через npm run dev там будет два запроса к /users/1, и первый помечен как canceled. Это не ошибка.

Кто это делает. <StrictMode> в main.tsx. Только в режиме разработки он для каждого компонента делает так:

  1. mountэффект запустился, уходит запрос №1
  2. unmountфункция очистки: запрос №1 отменён
  3. mountэффект запустился снова, запрос №2 — его данные и попадут на экран

Зачем. React проверяет, что у эффекта правильная функция очистки. Если очистки нет, ошибка проявится сразу при разработке, а не у пользователей:

ЭффектБез очистки при двойном запускеС очисткой
setIntervalдва таймера, счётчик идёт в 2 раза быстрееработает один таймер
addEventListenerобработчик срабатывает два разаодин обработчик
fetchдва запроса, ответы могут прийти не по порядкупервый отменён, данные от второго

Когда так не будет. В собранном проекте (npm run build и npm run preview) эффект срабатывает один раз.

Что делать. Ничего не отключать, просто всегда писать функцию очистки. Если при двойном запуске всё работает правильно, эффект написан верно.

Не прячьте проблему

Не убирайте <StrictMode> и не ставьте «защиту» через useRef, чтобы эффект срабатывал один раз. Так проблема не решается, а только скрывается.

3.5

Для справки: классовые компоненты

В старом коде встретятся методы жизненного цикла. Вот чему они соответствуют:

Классовый компонентФункциональный компонент
componentDidMountuseEffect(() => {...}, [])
componentDidUpdateuseEffect(() => {...}, [value])
componentWillUnmountreturn () => {...} внутри useEffect

3.6

Частые ошибки

  • Нет функции очистки у таймера или подпискиПосле ухода со страницы они продолжают работать и тратят память.
  • Забыли зависимостьЭффект использует userId, но в массиве его нет. При смене userId данные не перезагрузятся.
  • Объект или массив в зависимостяхЕсли он создаётся заново при каждой отрисовке, эффект будет срабатывать каждый раз.
  • Считаем данные в useEffectЕсли значение вычисляется из props или state, useEffect не нужен. Считаем прямо при отрисовке: const fullName = firstName + ' ' + lastName;

Навигация по сайту

4.1

Зачем нужен роутер

Наше приложение — SPA (Single Page Application): в браузер загружается одна HTML-страница, а всё остальное рисует React. Чтобы у сайта были разные страницы со своими адресами (/, /posts, /about), нужен роутер. Он:

  • смотрит на адрес в браузере и показывает нужную страницу;
  • переключает страницы без перезагрузки: быстро, состояние не теряется;
  • поддерживает кнопки «Назад» и «Вперёд» браузера.

Используем самую популярную библиотеку — React Router.

          <ListItemButton key={post.id} component={Link} to={`/posts/${post.id}`}>
            <ListItemText primary={post.title} />
          </ListItemButton>
        ))}
      </List>
    </>
  );
};
4.6

Параметры адреса и переход из кода

  • useParams достаёт параметры из адреса: для /posts/2 получим { id: '2' }.
  • useNavigate делает переход из кода: после отправки формы, по кнопке «Назад».
src/pages/PostPage/PostPage.tsx
import { useNavigate, useParams } from 'react-router';
import { Button, Typography } from '@mui/material';
import { posts } from '../../data/posts';

export const PostPage = () => {
  const { id } = useParams(); // id из адреса /posts/:id — всегда строка
  const navigate = useNavigate();

  const post = posts.find((p) => p.id === Number(id));

  if (!post) {
    return <Typography>Пост не найден</Typography>;
  }

  return (
    <>
      <Button onClick={() => navigate(-1)}>← Назад</Button>
      <Typography variant="h4" gutterBottom>
        {post.title}
      </Typography>
      <Typography>{post.text}</Typography>
    </>
  );
};

LoginForm.tsx
import { useNavigate } from 'react-router';

export const LoginForm = () => {

    // ...проверили логин и пароль

navigate(-1) — назад, как кнопка браузера. navigate('/path') — на указанную страницу.

4.9

Частые ошибки

  • <a href="/about"> вместо <Link to="/about">Страница полностью перезагружается, состояние теряется.
  • Забыли <Outlet /> в LayoutШапка есть, а страницы не появляются.
  • useNavigate или Link вне BrowserRouterВ консоли будет ошибка. BrowserRouter должен оборачивать всё приложение.
  • Сравниваем id из useParams с числомПараметр всегда строка, переводим так: Number(id).
  • На хостинге 404 при обновлении /postsСервер не знает про маршруты React. На хостинге нужно настроить, чтобы все адреса отдавали index.html. В npm run dev всё работает само.
